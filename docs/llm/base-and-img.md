# TSK base layer, image layer, `tsk/util/` and `tsk/libtsk.h`

The base layer (`tsk/base/`) supplies the types, error reporting, locks and small utilities that every other layer of The Sleuth Kit (TSK) C/C++ library uses.
The image layer (`tsk/img/`) opens a disk image in any supported container format and exposes it as one flat, read-only byte range through `TSK_IMG_INFO`.
`tsk/util/` holds crypto and encryption-detection helpers used by the upper layers, and `tsk/libtsk.h` is the one header that external code includes.
Read this file before you call `tsk_img_*` or `tsk_error_*`, write code that must build on both Linux (GCC) and Windows (MSVC), add an image backend, or touch anything under `tsk/base/`, `tsk/img/` or `tsk/util/`.
Volume systems and pools are in `vs-and-pool.md`, file systems in `fs.md`, `TskAuto` and hash databases in `auto-hashdb-cpp.md`, and building and testing in `build-and-test.md`.

All paths below are relative to the repository root. Line numbers drift, so every reference names a symbol.

## Headers and linking

External code includes exactly one header:

```c
#include <tsk/libtsk.h>
```

`tsk/libtsk.h` includes, in this order, `tsk/base/tsk_base.h`, `tsk/img/tsk_img.h`, `tsk/vs/tsk_vs.h`, `tsk/fs/tsk_fs.h`, `tsk/hashdb/tsk_hashdb.h`, `tsk/auto/tsk_auto.h` and `tsk/pool/tsk_pool.h`.
`tsk_base.h` and `tsk_img.h` both state that they are not meant to be included directly, and `tsk_img.h` does not compile alone because it relies on types from `tsk_base.h`.
Every include path starts with `tsk/`, so the `-I` directory must be the one that contains the `tsk/` directory (the repository root, or the install prefix's `include`).

Each layer has a public header and an internal header. Code inside the library includes the internal one, which includes the public one.

| Public, installed | Internal, not installed | What the internal header adds |
|---|---|---|
| `tsk/base/tsk_base.h`, `tsk_os.h`, `tsk_os_cpp.h` | `tsk/base/tsk_base_i.h`, `tsk_unicode.h`, `crc.h` | `tsk/tsk_config.h` (the autoconf `HAVE_*` macros), lock functions, `tsk_malloc`/`tsk_realloc`, endian macros, Unicode conversion, Windows `tsk_getopt` |
| `tsk/img/tsk_img.h` | `tsk/img/tsk_img_i.h` | `struct IMG_INFO`, `tsk_img_malloc`/`tsk_img_free`, image-name helpers, `tsk_img_read_legacy`, `tsk_img_read_no_cache` |

Two headers are generated by `configure` and do not exist in a fresh checkout:

- `tsk/tsk_incs.h` is installed. `tsk_base.h` includes it on every compiler except MSVC. It includes `<unistd.h>`, `<inttypes.h>` and `<sys/param.h>` when present, and it defines `TSK_MULTITHREAD_LIB` when pthreads were found and `--disable-multithreading` was not given (see `AC_CONFIG_COMMANDS([tsk/tsk_incs.h]` in `configure.ac`).
- `tsk/tsk_config.h` is not installed. It holds the `HAVE_LIB*` macros, so external code cannot test them at compile time. Call `tsk_img_type_supported()` at run time instead.

The installed header list is `nobase_include_HEADERS` in `Makefile.am`. Several installed headers include a header that is not installed, so they compile only inside the source tree:

- `tsk/img/logical_img.h` and `tsk/img/pool.hpp` include `tsk_img_i.h`.
- `tsk/util/detect_encryption.h` includes `tsk/base/tsk_base_i.h`.
- `tsk/util/Bitlocker/BitlockerParser.h`, `DataTypes.h`, `MetadataEntry.h` and `MetadataUtils.h` include `tsk_base_i.h` or `tsk_img_i.h`.
- `tsk/util/crypto.hpp` includes `tsk/tsk_config.h` when `HAVE_CONFIG_H` is defined.

Treat `libtsk.h` and what it pulls in as the only supported external interface.

The autotools build merges every layer into one library, `tsk/libtsk.la`, with no symbol-visibility restrictions. Link with `pkg-config --cflags --libs tsk` (`tsk/tsk.pc.in`); a static link needs `--static` to pick up the optional dependencies. The MSVC project `win32/libtsk/libtsk.vcxproj` builds a static library. See `build-and-test.md`.

## Platform model: `TSK_TCHAR`, `TSK_WIN32` and what the headers define

TSK stores all text it extracts from images as UTF-8 `char` strings on every platform.
Only strings that name things in the host environment (image paths, command-line arguments) use `TSK_TCHAR`, defined in `tsk/base/tsk_os.h`:

| | Windows (`TSK_WIN32`) | POSIX |
|---|---|---|
| `TSK_TCHAR` | `WCHAR`, UTF-16 | `char`, UTF-8 |
| `_TSK_T("x")` | `L"x"` | `"x"` |
| `PRIttocTSK` (print a `TSK_TCHAR*` with a `char` format string) | `"ls"` | `"s"` |
| `PRIcTSK` (print a `char*` with a `TSK_TCHAR` format string) | `L"hs"` | `"s"` |
| `PRIuSIZE` (print a `size_t`) | `"Iu"` | `"zu"` |
| `TSK_TSTRING` (`tsk_os_cpp.h`, not pulled in by `libtsk.h`) | `std::basic_string<wchar_t>` | `std::string` |

`tsk_os.h` also maps a family of `T*` macros (`TSTRLEN`, `TSTRCMP`, `TSTRNCPY`, `TSTRTOULL`, `TSTAT`/`STAT_STR`, `TFPRINTF`, `TSNPRINTF`, `GETOPT`/`OPTIND`/`OPTARG` and others) to the wide or narrow function. Use them in library code that handles `TSK_TCHAR`.

Rules that follow from this:

- A `TSK_TCHAR*` passed to a `char` printf-style function, including `tsk_error_set_errstr`, must use `"%" PRIttocTSK`, never `"%s"`.
- Code that has UTF-8 paths on every platform should call the `tsk_img_open_utf8*` functions, which convert to UTF-16 on Windows and pass the string through unchanged on POSIX.
- `tsk_os.h` defines `TSK_WIN32` for MSVC and for MinGW. For MSVC it also defines `TSK_MULTITHREAD_LIB`, `UNICODE`, `_UNICODE` and `WIN32_LEAN_AND_MEAN` and includes `<windows.h>`, so a Windows consumer is always a Unicode build. MinGW gets `TSK_MULTITHREAD_LIB` only through the generated `tsk_incs.h`.
- On MSVC `tsk_os.h` typedefs `ssize_t` (64-bit on `_WIN64`, otherwise 32-bit) and `mode_t`, unless `HAVE_SSIZE_T` is already defined. Define `HAVE_SSIZE_T` first if another header (for example Python's) provides `ssize_t`.

The public headers put many unprefixed names into the consumer's namespace. Expect collisions with these:

- All platforms: macros `FALLTHROUGH` and `UNUSED` (GCC attributes; empty on MSVC), `TRUE`/`FALSE` (if `TRUE` is undefined), typedefs `POINTER`, `UINT2`, `UINT4`, `BYTE`, and `Stats` (`tsk_img.h`).
- Windows: macros `strcasecmp`, `strncasecmp`, `putenv`, `unlink`, `fseeko`, `roundup`, `atoll` (MSVC) and `strtok_r(a,b,c)`, which expands to the non-reentrant `strtok(a,b)`. MinGW also gets `#define daddr_t int`.
- The library exports the globals `tsk_verbose` (declared) and `progname` (defined in `tsk_error.c`, not declared in any public header).

`TSK_ERROR_FORMAT_ATTRIBUTE` expands to a printf `format` attribute only under `__GNUC__`, so format-string mismatches in `tsk_error_set_errstr` calls are diagnosed by GCC and silently accepted by MSVC.

## Core types and return conventions

All of these are in `tsk/base/tsk_base.h`, each with `PRI*` macros defined beside it (for example `PRIuDADDR`, `PRIdOFF`, `PRIuINUM`).

- `TSK_OFF_T` is `int64_t`, **signed**, and holds byte offsets and sizes. Compare it against `size_t` values with care.
- `TSK_DADDR_T` is `uint64_t` and holds a sector or block address, not a byte offset.
- `TSK_INUM_T` (`uint64_t`) is a metadata address, `TSK_PNUM_T` (`uint32_t`) a partition index, `TSK_UID_T`/`TSK_GID_T` are `uint32_t`.

Return conventions used across the library:

- Functions that return a pointer return `NULL` on error.
- Functions that return `uint8_t` or `int` as a status return **0 on success and 1 on error** (`tsk_list_add`, `tsk_stack_push`, `tsk_parse_pnum`, `tsk_print_sanitized`, `TskImgInfo::open`). Predicates such as `tsk_list_find` and `tsk_stack_find` return 1 for "found".
- Read functions return `ssize_t`: a byte count, or -1 on error.
- `TSK_RETVAL_ENUM` distinguishes `TSK_OK`, `TSK_ERR` (abort), `TSK_COR` (this object is corrupt, the caller may continue with the next one) and `TSK_STOP` (stop, not an error).
- Walk callbacks return `TSK_WALK_RET_ENUM`: `TSK_WALK_CONT`, `TSK_WALK_STOP` (the walk returns success) or `TSK_WALK_ERROR` (the walk returns failure).
- Strings returned by `tsk_version_get_str`, `tsk_img_type_toname` and `tsk_img_type_todesc` are static. Memory that the library hands to the caller is released with `free()` unless a dedicated close or free function exists.

## Error handling

TSK reports failure through the return value and stores the details in a per-thread `TSK_ERROR_INFO` (`tsk_base.h`): an error number `t_errno`, a primary message `errstr`, a secondary message `errstr2`, and a scratch buffer `errstr_print`. Each string holds at most `TSK_ERROR_STRING_MAX_LENGTH` (1024) characters. The functions are implemented in `tsk/base/tsk_error.c`:

```c
TSK_ERROR_INFO *tsk_error_get_info();
uint32_t tsk_error_get_errno();
void tsk_error_set_errno(uint32_t t_errno);
char *tsk_error_get_errstr();
void tsk_error_set_errstr(const char *format, ...);
void tsk_error_vset_errstr(const char *format, va_list args);
char *tsk_error_get_errstr2();
void tsk_error_set_errstr2(const char *format, ...);
void tsk_error_vset_errstr2(const char *format, va_list args);
void tsk_error_errstr2_concat(const char *format, ...);
void tsk_error_set_error_listener(TSK_ERROR_LISTENER_CB listener);
const char *tsk_error_get();
void tsk_error_print(FILE *);
void tsk_error_reset();
```

Reading errors:

- `tsk_error_get()` returns `NULL` when the error number is 0. Otherwise it formats `"<text for the code> (<errstr>) (<errstr2>)"` into `errstr_print` and returns that buffer, with no trailing newline. `tsk_error_print(FILE*)` prints the same text plus a newline and prints nothing when there is no error.
- Every returned string points into the calling thread's storage and is overwritten by the next TSK call that sets or resets an error on that thread. Copy it if it must outlive that.
- An error number is a family bit ORed with a small code: `TSK_ERR_AUX`, `TSK_ERR_IMG`, `TSK_ERR_VS`, `TSK_ERR_FS`, `TSK_ERR_HDB`, `TSK_ERR_AUTO`, `TSK_ERR_POOL`. `TSK_ERR_MASK` extracts the code. The `TSK_ERR_IMG_*` codes are listed in `tsk_base.h`, and their texts are in the tables at the top of `tsk_error.c`.
- The error state is meaningful only after a function has reported failure. Functions do not clear it on success in general, although the public open functions and `tsk_img_read`'s argument checks call `tsk_error_reset()` first.

Setting errors inside the library follows one pattern, and the order matters:

```c
tsk_error_reset();
tsk_error_set_errno(TSK_ERR_IMG_ARG);
tsk_error_set_errstr("my_func: bad sector size %u", ssize);
return NULL;
```

`tsk_error_set_errstr` and `tsk_error_vset_errstr` invoke the error listener with the current error number, so the number must be set first. The `errstr2` setters do not invoke the listener; callers higher in the stack use `errstr2` or `tsk_error_errstr2_concat` (which appends a space and the new text) to add context without replacing the original message. When adding a new error code, add the `#define`, bump the family's `*_MAX`, and add the string at the same index in the family's table in `tsk_error.c`.

Where the storage lives depends on the build:

- POSIX with `TSK_MULTITHREAD_LIB`: one heap block per thread, held in a pthread key and freed by a key destructor when the thread exits.
- Windows with `TSK_MULTITHREAD_LIB` (always, for MSVC): one heap block per thread in a TLS slot (`tsk_error_win32_get_per_thread_` in `tsk_error_win32.cpp`). Nothing frees it automatically; see "Known defects and traps".
- Without `TSK_MULTITHREAD_LIB`: a single static struct, shared by all threads.

The error listener (`tsk_error_set_error_listener`) and `tsk_verbose` are plain process-wide globals with no synchronisation. Setting `tsk_verbose` non-zero makes the library print debug messages to `stderr`. In C++, `class TskError` offers static `get()`, `print(FILE*)` and `reset()` wrappers.

## Threading and locks

`tsk_lock_t` is defined in the public `tsk_base.h` because public structs in other layers embed it, but the functions `tsk_init_lock`, `tsk_deinit_lock`, `tsk_take_lock` and `tsk_release_lock` are internal (`tsk_base_i.h`, `tsk/base/tsk_lock.c`).

- With `TSK_MULTITHREAD_LIB` it wraps a `CRITICAL_SECTION` on Windows and a default `pthread_mutex_t` elsewhere. Without it, it is a dummy struct and all four functions do nothing.
- The Windows lock is recursive and the pthread mutex is not. Code that takes the same lock twice on one thread works on Windows and deadlocks on Linux. Never call back into a function that takes a lock you already hold.
- A pthread failure prints to `stderr` and hits `assert(0)`.
- The size of `tsk_lock_t`, and so the layout of every struct that embeds it, depends on `TSK_MULTITHREAD_LIB`. A consumer must see the same definition as the library build, which the installed `tsk_incs.h` guarantees. Do not define or undefine the macro by hand.

Thread-safety contract for this layer:

- Error state is per thread in multithreaded builds.
- One `TSK_IMG_INFO` may be read from several threads in a multithreaded build. Reads on the same handle are fully serialised (see "Reading"). In a single-threaded build the locks are no-ops and sharing a handle is not safe.
- `tsk_verbose`, the error listener, `TSK_STACK`, `TSK_LIST` and the hash contexts have no locking.

## Image layer

### Mental model

`TSK_IMG_INFO` (`tsk/img/tsk_img.h`) is the public view of an open image. The library actually allocates a larger backend-specific struct whose first member is the internal `struct IMG_INFO` (`tsk/img/tsk_img_i.h`), whose first member is in turn the `TSK_IMG_INFO`. The same pointer is cast between the three.

```
TSK_IMG_INFO          public: tag, itype, size, num_img, sector_size, page_size, spare_size, images
  inside IMG_INFO     internal: cache, stats, cache_read, read, close, imgstat
    inside IMG_RAW_INFO / IMG_EWF_INFO / ...   backend state, file handles, a read_lock
```

- `read`, `close` and `imgstat` are the backend's functions. `cache_read` is the entry point that `tsk_img_read` calls; it is always `tsk_img_read_legacy`. `cache` points to a `LegacyCache` (`tsk/img/legacy_cache.h`).
- There is no public function that calls `imgstat`. The `img_stat` tool includes the internal header to reach it.
- Field meanings that are not obvious: `tag` is `TSK_IMG_INFO_TAG` while the struct is live and 0 after `tsk_img_free`; `size` is the logical (decompressed) size in bytes; `images`/`num_img` are the library's own copies of the paths and can list more files than the caller passed, because the raw and EWF backends discover sibling segments; `page_size` and `spare_size` are never set by the image layer and read as 0, despite the header comments that give defaults.
- `TSK_IMG_OPTIONS` and the `*_opt` open functions exist, but the struct has only a `dummy` member and `img_open()` ignores it.

### Opening

Signatures from `tsk/img/tsk_img.h` (each also has a `_opt` twin taking a trailing `const TSK_IMG_OPTIONS *opts`):

```c
TSK_IMG_INFO *tsk_img_open_sing(const TSK_TCHAR *a_image, TSK_IMG_TYPE_ENUM type, unsigned int a_ssize);
TSK_IMG_INFO *tsk_img_open(int num_img, const TSK_TCHAR *const images[], TSK_IMG_TYPE_ENUM, unsigned int a_ssize);
TSK_IMG_INFO *tsk_img_open_utf8_sing(const char *a_image, TSK_IMG_TYPE_ENUM type, unsigned int a_ssize);
TSK_IMG_INFO *tsk_img_open_utf8(int num_img, const char *const images[], TSK_IMG_TYPE_ENUM type, unsigned int a_ssize);
void tsk_img_close(TSK_IMG_INFO *);
```

All of them funnel into `tsk_img_open_opt` or `tsk_img_open_utf8_opt` and then the internal `img_open()` in `tsk/img/img_open.cpp`.

- The error state is reset on entry.
- `num_img < 0` fails with `TSK_ERR_IMG_ARG`. `num_img == 0`, a `NULL` array or a `NULL` first path fails with `TSK_ERR_IMG_NOFILE` (`images_ok` in `img_open.h`).
- `a_ssize` is the device sector size in bytes. It must be 0 (use the backend default, normally 512) or a multiple of 512; anything else fails with `TSK_ERR_IMG_ARG` (`sector_size_ok`).
- For split images, pass the segment paths in order. The path strings are copied, so the caller may free its array as soon as the call returns.
- An explicit `type` selects one backend (`img_open_by_type`). A type that is not compiled in, `TSK_IMG_TYPE_EXTERNAL`, `TSK_IMG_TYPE_POOL` or an OR of several bits fails with `TSK_ERR_IMG_UNSUPTYPE`.

`TSK_IMG_TYPE_DETECT` (0) runs `img_open_detect_type`:

1. It tries each compiled-in non-raw backend in the order AFF, EWF, AFF4, VMDK, VHD, QCOW, resetting the error state before each attempt.
2. If exactly one succeeds, that handle is returned.
3. If none succeeds, it tries raw. Raw accepts any readable regular file or device, so an unrecognised container opens as raw. If raw fails too, the error is replaced with a bare `TSK_ERR_IMG_UNKTYPE`.
4. If more than one succeeds, it fails with `TSK_ERR_IMG_UNKTYPE` and an `errstr` listing the candidates, for example `"EWF, VMDK"`.
5. An AFF open that fails with `TSK_ERR_IMG_PASSWD` ends detection immediately with that error.

### Reading

```c
ssize_t tsk_img_read(TSK_IMG_INFO *img, TSK_OFF_T off, char *buf, size_t len);
```

- `off` is a byte offset from the start of the image and need not be sector-aligned.
- It returns the number of bytes read, which is less than `len` when the request runs past the end of the image.
- It returns -1 with `TSK_ERR_IMG_ARG` for a `NULL` image or buffer, a negative `off`, or a `len` that does not fit in a signed 64-bit value.
- It returns **-1 with `TSK_ERR_IMG_READ_OFF` when `off >= img->size`**. It does not return 0 at end of image as POSIX `read` does. Loop on `off < img->size`, not on a zero return.

Caching and locking (`tsk_img_read_legacy` in `tsk/img/img_io.cpp`):

- Each open image owns one `LegacyCache`: `TSK_IMG_INFO_CACHE_NUM` (32) blocks of `TSK_IMG_INFO_CACHE_LEN` (65536) bytes, about 2 MiB per handle, plus one lock.
- The cache lock is held for the entire call, including the backend read. Reads on one handle never run in parallel; open the image again to get an independent handle.
- A miss loads a 64 KiB block starting at `off` rounded down to 512 bytes, replacing the least recently useful entry. A request with `len + (off % 512) > 65536` bypasses the cache and goes to the backend with `len` rounded up to a multiple of `sector_size` (`img_read_no_cache`).
- If the backend returns 0 or less while filling a cache block, the read is retried once without the cache. A failing backend `read` is therefore called twice per request.

### Closing and ownership

- The caller owns the returned `TSK_IMG_INFO*` and releases it with `tsk_img_close`, which accepts `NULL`. It deletes the cache and then calls the backend `close`, which frees the whole struct.
- Close an image only after every volume system, pool and file system opened on top of it is closed, and after all threads have finished reading from it. The upper layers keep a pointer to the image and do not close it; see `vs-and-pool.md` and `fs.md`.

### Minimal example

This compiles as C or C++ on Linux and Windows. `tsk_img_open_utf8_sing` avoids `TSK_TCHAR` handling in the caller.

```c
#include <tsk/libtsk.h>

int main(int argc, char **argv)
{
    char buf[512];
    TSK_IMG_INFO *img;
    ssize_t cnt;

    if (argc != 2) {
        fprintf(stderr, "usage: %s image\n", argv[0]);
        return 1;
    }

    img = tsk_img_open_utf8_sing(argv[1], TSK_IMG_TYPE_DETECT, 0);
    if (img == NULL) {
        tsk_error_print(stderr);
        return 1;
    }
    printf("type=%s size=%" PRIdOFF " sector=%u\n",
        tsk_img_type_toname(img->itype) ? tsk_img_type_toname(img->itype) : "?",
        img->size, img->sector_size);

    cnt = tsk_img_read(img, 0, buf, sizeof(buf));
    if (cnt < 0) {
        tsk_error_print(stderr);
        tsk_img_close(img);
        return 1;
    }
    printf("read %" PRIuSIZE " bytes\n", (size_t) cnt);

    tsk_img_close(img);
    return 0;
}
```

On Windows `argv` from `main` is in the ANSI code page, not UTF-8; real tools take wide arguments and call `tsk_img_open_sing`.

### Formats and backends

| Format | Type constant | Compiled in when | Backend file | Notes |
|---|---|---|---|---|
| Raw, single or split | `TSK_IMG_TYPE_RAW` | always | `raw.cpp` | Segment discovery, see below |
| AFF, AFD, AFM, any AFFLIB | `TSK_IMG_TYPE_AFF_*` | `HAVE_LIBAFFLIB` | `aff.c` | One path only. On Windows a path with non-ASCII characters is rejected |
| EWF (E01) | `TSK_IMG_TYPE_EWF_EWF` | `HAVE_LIBEWF` | `ewf.cpp` | Given one path, globs the other segments. Uses the sector size stored in the file when `a_ssize` is 0 |
| VMDK | `TSK_IMG_TYPE_VMDK_VMDK` | `HAVE_LIBVMDK` | `vmdk.cpp` | One path only |
| VHD | `TSK_IMG_TYPE_VHD_VHD` | `HAVE_LIBVHDI` | `vhd.cpp` | One path only |
| QCOW | `TSK_IMG_TYPE_QCOW_QCOW` | `HAVE_LIBQCOW` | `qcow.cpp` | One path only |
| AFF4 | `TSK_IMG_TYPE_AFF4_AFF4` | `HAVE_LIBAFF4` | `aff4.cpp` | One path only. Ignores `a_ssize`; sector size is always 512 |
| Logical directory | `TSK_IMG_TYPE_LOGICAL` | always, works on Windows only | `logical_img.cpp` | See below |
| External | `TSK_IMG_TYPE_EXTERNAL` | always | `tsk_img_open_external` | Not openable by type |
| Pool volume | `TSK_IMG_TYPE_POOL` | always | `pool.hpp` | Created by the pool layer; see `vs-and-pool.md` |

- The type constants are single bits. `tsk_img_type_supported()` returns the OR of the types compiled in, and it is the only way for external code to learn which formats exist. `tsk_img_type_toname`/`tsk_img_type_todesc` return `NULL` for a type that is not in the compiled table (`img_open_table` in `img_types.c`), which includes `EXTERNAL`, `POOL` and, off Windows, `LOGICAL`.
- The type names accepted by `tsk_img_type_toid` and `tsk_img_type_toid_utf8` are `raw`, `aff`, `afd`, `afm`, `afflib`, `ewf`, `aff4`, `vmdk`, `vhd`, `qcow` and, on Windows, `logical`. Unknown names give `TSK_IMG_TYPE_UNSUPP`.
- The MSVC project defines `HAVE_LIBEWF`, `HAVE_LIBVMDK` and `HAVE_LIBVHDI` in its full configurations and never defines the AFF, AFF4 or QCOW macros, so those three formats are autotools-only.
- Raw backend: when given exactly one path that is not a Windows device, `raw_open` calls `tsk_img_findFiles` (`mult_files.cpp`) and silently appends sibling segments that exist on disk. Recognised first-segment names end in a zero-padded number after `.` or `_` (`.000`, `.001`, `_001`), in an all-`a` run after `.`, `_` or `x` (`.aaa`, `xaa`), in `.dmg` (followed by `.002.dmgpart`), or in `.bin` (followed by `(2).bin`). Passing more than one path disables discovery. A directory is rejected with `TSK_ERR_IMG_MAGIC`. On Windows, paths starting `\\.\` or `\\?\` are device objects, and for `\\.\` devices with `a_ssize == 0` the sector size is probed between 512 and 4096.
- Logical directory backend: it presents a directory tree as an "image" for the logical file-system code in `fs.md`. `size` is `INT64_MAX`, and off Windows `logical_open` fails with `TSK_ERR_IMG_ARG`.
- Image writer (`img_writer.h`, internal): `tsk_img_writer_create` copies a raw image to a VHD as it is read. It is implemented on Windows only and returns `TSK_ERR` elsewhere.

### Adding or supplying a backend

Inside the library, follow `raw_open` in `raw.cpp`:

1. Allocate a struct whose first member is `IMG_INFO` with `tsk_img_malloc(sizeof(MyInfo))`. The memory is zeroed and `tag` is set.
2. Fill `itype`, `size` and `sector_size`, and store the paths with `tsk_img_copy_image_names`, which returns **1 on success and 0 on failure**, the reverse of the usual convention.
3. Set `read`, `close` and `imgstat`. `read` returns a byte count or -1 after setting the TSK error. It runs with the cache lock held, so it must not call `tsk_img_read` on the same image. It can be asked for more bytes than remain in the image and must clip the request itself. `close` releases backend resources and ends with `tsk_img_free(ptr)`. It must not delete `IMG_INFO::cache`, because `tsk_img_close` already did.
4. Add a `case` to `img_open_by_type`, an entry to `img_open_table` in `img_types.c`, and, if the format has a signature, an entry in the `types` list of `img_open_detect_type`. `img_open()` installs the cache after the backend returns.
5. Reject an unsupported `num_img` with both an error number and a message.

From outside the library, the public hook is:

```c
TSK_IMG_INFO *tsk_img_open_external(void *ext_img_info, TSK_OFF_T size, unsigned int sector_size,
    ssize_t (*read)(TSK_IMG_INFO *img, TSK_OFF_T off, char *buf, size_t len),
    void (*close)(TSK_IMG_INFO *),
    void (*imgstat)(TSK_IMG_INFO *, FILE *));
```

All three callbacks and the pointer must be non-`NULL`, or it fails with `TSK_ERR_IMG_ARG`. The function sets `tag`, `itype`, `size` and `sector_size` (0 becomes 512), creates the cache, and returns the same pointer. It also stores `cache`, `cache_read`, `read`, `close` and `imgstat` in the **internal `IMG_INFO` layout**, so `ext_img_info` must point to zero-initialised storage that begins with a complete `IMG_INFO`, not just a `TSK_IMG_INFO`. Because `IMG_INFO` is declared only in the non-installed `tsk_img_i.h`, a caller outside the source tree has to mirror that struct, and must re-check it when upgrading. The `close` callback owns freeing the storage. No code in this repository calls `tsk_img_open_external`.

### C++ wrapper `TskImgInfo`

`class TskImgInfo` (`tsk_img.h`) wraps the C calls: `open` (returns 0 on success, 1 on error), `read`, `getType`, `getSize`, `getSectorSize` and static type helpers. It is not copyable. The `open` overloads that take UTF-8 `const char*` exist only under `TSK_WIN32`; on POSIX the `TSK_TCHAR` overloads already take `char`. Its ownership behaviour is a trap described at the end of this file.

## Other base utilities

- **Hashing.** `TSK_MD5_Init/Update/Final` with `TSK_MD5_CTX`, and `TSK_SHA_Init/Update/Final` with `TSK_SHA_CTX`. The "SHA" functions are SHA-1. `TSK_SHA_Final` writes 20 bytes; `TSK_SHA_DIGEST_LENGTH` is 32, so a buffer of that size is safe, but do not use the macro as the digest length. Update lengths are `unsigned int`, so feed large data in chunks. Contexts are independent and unlocked. `TSK_BASE_HASH_ENUM` is the flag type the upper layers use to select hashes.
- **`TSK_LIST`.** A set of `uint64_t` values stored as descending runs: an entry with `key` 6 and `len` 2 holds 6 and 5. `tsk_list_add(&head, key)` creates the list when `head` is `NULL` and ignores duplicates. Free it with `tsk_list_free`.
- **`TSK_STACK`.** A growable `uint64_t` stack used to detect directory loops: `tsk_stack_create`, `tsk_stack_push`, `tsk_stack_pop`, `tsk_stack_find` (linear scan), `tsk_stack_free`.
- **Printing.** `tsk_fprintf` and `tsk_printf` take a UTF-8 format string and UTF-8 `%s` arguments on every platform, and on Windows convert the result to UTF-16 before output. Library code uses them instead of `fprintf` for anything that may contain file names. `tsk_print_sanitized` prints a string with control characters replaced by `^`.
- **Parsing.** `tsk_parse_offset` returns a count of sectors, not bytes, as `TSK_OFF_T`, or -1 with `TSK_ERR_IMG_OFFSET`; it returns 0 for `NULL`. `tsk_parse_pnum` returns 0 on success.
- **Unicode (internal, `tsk_unicode.h`).** `tsk_UTF8toUTF16`, `tsk_UTF16toUTF8` (takes the source byte order as a `TSK_ENDIAN_ENUM`), `tsk_UTF16toUTF8_lclorder`, `tsk_UTF16WtoUTF8_lclorder`, `tsk_isLegalUTF8Sequence`, `tsk_cleanupUTF8`, `tsk_cleanupUTF16`. The converters take pointers to the source and target cursors and advance them; end pointers are one past the last element; the output is not NUL-terminated, so the caller writes the terminator through the advanced target pointer. `UTF16` is `unsigned short`, which matches `wchar_t` only on Windows.
- **Memory (internal, `mymalloc.c`).** `tsk_malloc` returns zeroed memory (it calls `calloc`) and on failure sets `TSK_ERR_AUX_MALLOC` and returns `NULL`. `tsk_realloc` on failure sets the error, returns `NULL` and leaves the original block allocated. Both are released with `free()`.
- **Endian (internal, `tsk_base_i.h`).** The macros `tsk_getu16`, `tsk_getu24`, `tsk_getu32`, `tsk_getu48`, `tsk_getu64` and signed `tsk_gets16/32/64` read from a byte pointer given a `TSK_ENDIAN_ENUM`. `tsk_guess_end_u16/u32/u64(&flag, bytes, expected)` sets `flag` to the order under which the bytes equal `expected` and returns 0, or returns 1 if neither order matches. Only `TSK_ENDIAN_ENUM` itself is public.
- **Version.** `TSK_VERSION_STR`, `TSK_VERSION_NUM`, `tsk_version_get_str()`, `tsk_version_print(FILE*)`. There is no run-time accessor for the numeric form.

## `tsk/util/`

These are helpers for the other layers. Their headers are installed but are not part of `libtsk.h`, and most do not compile outside the source tree (see "Headers and linking").

- `crypto.hpp`/`crypto.cpp`: `aes_xts_decryptor`, `pbkdf2_hmac_sha256`, `rfc3394_key_unwrap`, `hash_buffer_md5`, `hash_buffer_sha256`, used by APFS. The whole file is inside `#ifdef HAVE_LIBCRYPTO` (OpenSSL). The free functions return `std::unique_ptr<uint8_t[]>`.
- `Bitlocker/`: the BitLocker volume parser used by the file-system layer (see `fs.md`). Every file is inside `#ifdef HAVE_LIBMBEDTLS`. `configure.ac` has no check that defines that macro; only `win32/libtsk/libtsk.vcxproj` defines it. An autotools build therefore compiles this code to nothing unless the macro is supplied by hand.
- `detect_encryption.h`/`.c`: `detectVolumeEncryption(TSK_IMG_INFO*, TSK_DADDR_T offset)` and `detectDiskEncryption(...)` return a heap-allocated `encryption_detected_result` (`encryptionType` plus a `desc` string) that the caller releases with `free()`, or `NULL` if allocation failed. A read failure yields a result of `ENCRYPTION_DETECTED_NONE`, not an error. Despite its type, `offset` is a byte offset passed straight to `tsk_img_read`. The file is compiled as C and the header has no `extern "C"` guard, so a C++ file must wrap the include in `extern "C" { }` to call these.
- `file_system_utils.h`/`.cpp`: `get_size_of_file_on_disk(path, is_winobj)` returns the size in bytes, -1 if the size is unknown, -2 if the file cannot be stat'ed or opened (TSK error set), or -3 if it is a directory (TSK error set). `is_windows_device_path` exists only under `TSK_WIN32`. The header includes nothing, so include a TSK base header first.
- `lw_shared_ptr.hpp`: a reference-counted pointer with a non-atomic count. Copies must not be created or destroyed concurrently. It also defines global `in_place_t` and `in_place`.
- `span.hpp`: a minimal `span<T>` used by the APFS code.

`tsk/img/unsupported_types.h` declares the internal `detectUnsupportedImageType(TSK_IMG_INFO*)`, which names known containers that TSK cannot open (for example 7z, gzip and bzip2 archives) and returns a `free()`-able string or `NULL`.

## Where the upstream Doxygen pages are wrong

The pages are in `tsk/docs/*.dox` (not the top-level `docs/`).

- `base.dox` tells readers to read "the global tsk_errno value". No such symbol exists; call `tsk_error_get_errno()`.
- `base.dox` presents `tsk_UTF16toUTF8()` and `tsk_UTF8toUTF16()` as public. They are declared only in the non-installed `tsk_unicode.h`. The symbols are exported, so external code can call them only by declaring the prototypes and types itself.
- `base.dox` does not mention that error state is per thread, the error listener, or `errstr2`.
- `basics.dox` says to add `-lewf` and `-lafflib` by hand; use `pkg-config`. Its Windows section refers to a `sleuthkit-3.0.0` directory and "five library layers".
- `img.dox` says the raw type is assumed when detection fails. Detection also fails outright when two non-raw formats match. The page omits the `_opt` functions, `tsk_img_open_external`, the cache, the sector-size check, raw segment discovery, and the -1 result for a read at or past the end.
- The comment on `tsk_img_open_external` in `img_open.cpp` says the pointer "must be castable to a TSK_IMG_INFO pointer". It must point to an `IMG_INFO`.
- The comment on `TSK_VERSION_NUM` says each version component is one byte (3.1.2 is `0x030102FF`). The value in the tree, `0x041400ff`, writes the minor version as decimal digits.

## Known defects and traps

Each item was confirmed by reading the named symbol in this checkout.

Error handling:

- `tsk_base.h`, `TSK_ERR_POOL_UNSUPTYPE` is defined as `(TSK_ERR_IMG | 1)`, the same value as `TSK_ERR_IMG_OFFSET`. It prints as "Invalid image offset" and cannot be told apart by number.
- `tsk_base.h`, `TSK_ERR_HDB_CORRUPT` and `TSK_ERR_HDB_UNSUPFUNC` are both `(TSK_ERR_HDB | 11)`.
- `tsk_base.h`, `TSK_ERR_AUX_GENERIC` is `(TSK_ERR_AUX | 2)` while `TSK_ERR_AUX_MAX` is 2 and the "TSK Error" text sits at index 1 of `tsk_err_aux_str`. `tsk_error_get` therefore prints `auxtools error: 2` for it.
- `tsk_error.c`, `tsk_error_get_info` (pthread variant) returns `NULL` if `malloc` fails. Only `tsk_error_reset` checks for that; every other accessor dereferences the result.
- `tsk_error_win32.cpp`, `tsk_error_win32_get_per_thread_` calls `memset` on an unchecked `malloc` result. The per-thread block is freed only by `tsk_error_win32_thread_cleanup()`, which no header declares. A Windows program that creates many short-lived threads calling TSK must declare it (`extern "C" void tsk_error_win32_thread_cleanup();`) and call it before each thread exits, or it leaks about 3 KiB per thread.
- `aff_open`, `aff4_open`, `vmdk_open`, `vhdi_open` and `qcow_open` reject `num_img != 1` by setting only `errstr`. The error number stays 0, so `tsk_error_get()` returns `NULL` and `tsk_error_print` prints nothing even though the open returned `NULL`. This is reachable by passing several paths with an explicit type.
- `img_open.cpp`, `img_open_detect_type`: when no format matches and raw also fails, the specific cause (for example "No such file or directory" from `get_size_of_file_on_disk`) is discarded and only `TSK_ERR_IMG_UNKTYPE` remains. Pass `TSK_IMG_TYPE_RAW` explicitly, or check the path yourself, to see the real error.

Image layer:

- `img_io.cpp`, `tsk_img_read` returns -1 at end of image (see "Reading"). The source carries a TODO about it.
- `raw.cpp`, `raw_open` accepts a single file whose size cannot be determined (`get_size_of_file_on_disk` returns -1) and stores `size == -1`. Every later `tsk_img_read` then fails with `TSK_ERR_IMG_READ_OFF`.
- `raw.cpp`, `set_device_sector_size` (Windows only) leaks its 4096-byte probe buffer when the device does not need sector-aligned reads.
- `logical_img.cpp`, `logical_read` sets `TSK_ERR_IMG_READ` and returns **0**, not -1. A `tsk_img_read` on a logical image therefore returns 0 with the error set, never data; the logical file-system code reads files by other means.
- `tsk_img.h`, `TskImgInfo::~TskImgInfo` always calls `tsk_img_close(m_imgInfo)` and ignores `m_opened`. The constructor `TskImgInfo(TSK_IMG_INFO*)` therefore takes ownership of the handle; closing that handle yourself as well is a double free. Calling `open()` twice leaks the first handle.
- `img_types.c`, `tsk_img_type_toid` and `tsk_img_type_toid_utf8` `assert` on `NULL` and crash in release builds.
- `unsupported_types.cpp`, `detectUnsupportedImageType` stores the `ssize_t` result of `tsk_img_read` in a `size_t` and tests only for 0, so a failed read (-1) is treated as a huge successful one.
- `configure.ac`, the final summary prints the libbfio result under the label "libqcow support" and the libqcow result under "libbfio support".

Base layer:

- `tsk_base.h`, `TSK_VERSION_NUM` (`0x041400ff`) and `TSK_VERSION_STR` (`"4.15.0-develop"`) disagree. Do not gate code on the numeric macro.
- `tsk_parse.c`, `tsk_parse_offset` strips leading `0` characters before calling `strtoull` with base 0. `"0x10"` becomes `"x10"` and is rejected, and `"010"` parses as decimal 10. Hexadecimal input is impossible.
- `tsk_parse.c`, `tsk_parse_pnum` returns 0 (success) for a `NULL` string without writing `*a_pnum`. Initialise the output first.
- `tsk_stack.c`: `tsk_stack_pop` on an empty stack underflows `top`; `tsk_stack_free(NULL)` dereferences `NULL`; when `tsk_stack_push` fails to grow, it overwrites `vals` with `NULL`, leaking the old buffer and leaving the stack unusable.
- `tsk_printf.c`, `tsk_fprintf` and `tsk_printf` on Windows format into a fixed 2048-character wide buffer (`tsk_printf_conv`). Longer output is truncated without any indication.
- `tsk_lock.c`: recursive on Windows, non-recursive on POSIX (see "Threading and locks"). A double lock that passes MSVC testing hangs on Linux.
- `tsk_os.h`, `#define strtok_r(a,b,c) strtok(a,b)` on Windows silently removes reentrancy from any consumer code that calls `strtok_r` after including `libtsk.h`.
